## 3. Kill-chains A–D, delta notes

- **A — reply steers the agent to post/DM secrets.** `x_bookmarks_list` is a new ingest
  channel for attacker-authored text (a bookmarked hostile post), but it enters through
  the same sanitize/cap/mark pipeline as timelines, and the outbound half of the chain
  (policy cells for `post_create`/`dm_send`) is unchanged. `x_post_hide_reply` gives an
  injected agent a new low-harm verb at publish+; hiding is reversible and visible to the
  conversation owner. **Verdict unchanged.**
- **B — lethal trifecta via `dm_send`.** The trifecta's private-data leg explicitly lists
  bookmarks, and the read half now exists in every preset (see O1). The chain still does
  not close: the exfil leg requires `write:dm`, which remains outside **all** presets
  (`src/core/policy.ts` — `read:dm`/`write:dm` in no preset), and public-write exfil
  requires publish+, same as before. **Closed as before; the private-data leg is wider on
  paper, the choke point is intact.**
- **C — policy-error unlock hint.** Denials for both new tools flow through the same
  `deniedToolError`, naming only the cell, never an env var (F2 fix applies to them
  automatically). **Verdict unchanged.**
- **D — base-URL confused deputy.** Both new endpoints are relative-path,
  `encodeURIComponent`-interpolated calls under the F1 hardcoded egress allowlist.
  **Closed as before.**
